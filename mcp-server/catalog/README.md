# Part catalog

`utils/pcb_builder.py:load_catalog()` merges two tiers and applies the sourcing overlay. Curated `part_id`s always win over imported ones.

| File | Role | Edit? |
|---|---|---|
| `curated_parts.json` | Hand-reviewed parts (`tier: "curated"`) | No — generated by `scripts/enrich_catalog.py`; edit the script |
| `import_manifest.json` | Whitelist of KiCad symbol/footprint pairs to import | Yes |
| `imported_parts.json` | Imported parts (`tier: "imported"`) | No — generated by `scripts/import_kicad.py` |
| `sourcing_queries.json` | How to find each part (MPN patterns, package, manufacturer) | Yes |
| `sourcing.json` | LCSC code / price / stock overlay | No — generated by `scripts/refresh_sourcing.py` |
| `footprint_checks.json` | EasyEDA footprint cross-check results | No — generated by `scripts/check_footprints.py` |
| `footprint_check_explanations.json` | Datasheet explanations for specific mismatches | Yes |
| `NOTICE.md`, `licenses/` | Third-party licenses | Keep with the data |

Each part has pins (number + name + function), a SPICE model and pin mapping (or none), the full embedded footprint S-expression, LCSC id and unit price.

## Imported tier (KiCad libraries)

`python mcp-server/scripts/import_kicad.py` reads `import_manifest.json`, parses the installed KiCad symbol (`pins`) and footprint (`pads`) libraries (`/usr/share/kicad`, or `KICAD_SYMBOL_DIR` / `KICAD_FOOTPRINT_DIR`) and writes `imported_parts.json`, re-emitting each footprint in the simplified self-contained form. `--search LIBRARY [GLOB]` lists symbols and their default footprints.

- Imported parts have an `unreviewed` footprint and only the ratings/support parts written in the manifest.
- Symbols whose pins have no matching pad are skipped with a reason.
- Manifest entries may carry `pin_names` (rename pins, e.g. the `+`/`-` of op-amp units), `spice` (below) and `fabrication` (`min_layer_count`, `fabricator_profile`, `reason`) for parts that only route on a finer process, such as the RP2040's 0.4 mm QFN.
- Every imported part records its source symbol/footprint and library version in `import`.

**Licensing.** The imported data is CC-BY-SA-4.0 with the KiCad libraries exception: designs and generated files are exempt, but redistributing `imported_parts.json` is not. Keep `NOTICE.md` and `licenses/` with it and share that file under CC-BY-SA-4.0.

## Generic SPICE models

A manifest `spice` block gives a part a generic model (`spice_model.kind == "generic"`). `utils/spice_models.py` renders whitelisted templates (`diode`, `npn`, `pnp`, `nmos`, `pmos`, `ldo`, `adjustable_reg`, `opamp`, `comparator_oc`, `resistor`, `inductor`, `optocoupler`) from `roles` (template terminal → pad number) and `params`.

These are datasheet-tuned approximations, not vendor models: `simulation_coverage` lists them as `generic_model_components` and the run warns that results are indicative. Parts without a model are reported as unmodeled. Add a template in `spice_models.py`, with a behavior test in `tests/test_imported_simulation.py`, before using it from the manifest.

## Sourcing

`python mcp-server/scripts/refresh_sourcing.py --download DIR` fetches the public jlcparts database (about 230 MB, 1.7 GB unpacked); `--db DIR/cache.sqlite3` writes `sourcing.json` (LCSC code, quantity-1 USD price, stock, JLCPCB basic/extended, alternates, data date).

- Selection prefers in-stock JLCPCB basic parts.
- Codes that cannot be verified are cleared, not guessed.
- R and C stay blank in the BOM on purpose: the value decides the order code.
- Prices are estimates from the data date, not quotes.

## Footprint cross-check (evidence only)

`python mcp-server/scripts/check_footprints.py` fetches the footprint of each part's sourced LCSC code from the EasyEDA public API (`easyeda.com/api/products/<LCSC>/components`; pad units are 10 mil; responses cached in gitignored `mcp-server/.cache/easyeda/`; backs off on HTTP 403/429/503). `utils/footprint_check.py` compares pads by number, position and size, aligned by pad 1 or centroid, allowing any 90° rotation or Y mirror (default tolerances 0.1 mm position, 0.15 mm size).

Results go to `footprint_checks.json`, keyed by part_id: `status` (pass | mismatch | no_reference | error), `worst_delta_mm`, `checked_at`, `source`, `reasons`. They surface in `get_part_details` (`footprint_cross_check`), in `readiness.footprint_review`, and as a `normalize_design` warning for placed mismatching parts.

Many mismatches are benign land-pattern differences between KiCad and EasyEDA; treat one as a prompt to compare against the manufacturer drawing. To help with that, the check also reports:

- `renumbering`: the pads have the same shape, but the two libraries number them differently. Pin functions still have to be checked against the datasheet.
- `pad spacing differs`: for two-pad parts, such as the lead-bend pitch of an axial diode.

**Explained mismatches.** Once a mismatch has been compared with the manufacturer drawing, record why in `footprint_check_explanations.json` (hand-edited): `lcsc` and `worst_delta_mm` of the exact result, `reason`, `evidence`, `recorded_by`, `recorded_at`. `load_footprint_checks()` then reports status `explained`, and `normalize_design` no longer warns. Readiness still lists the part, because an explained difference is not a review. An explanation applies only to the result it was written for. If the sourced part or footprint changes, the check goes back to `mismatch` and says the explanation is stale. `tests/test_footprint_check.py` fails when a recorded explanation no longer matches.

A cross-check never marks a footprint `reviewed`: that still requires `manufacturer_drawing`, `review_evidence` and `reviewed_by`. Data is from the JLCEDA/EasyEDA Official Library (https://easyeda.com), which requires source attribution.
